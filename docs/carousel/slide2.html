The Engineering Problem Why 90% of RAG Demos Fail in Production
Slide 2 of 6

Tutorial notebooks work with 5-line toy scripts, but real enterprise deployments hit severe memory, privacy, and hallucination constraints. Here is how we engineered around them:

✕ 1. Heavy PyTorch OOM Container Crashes

Standard sentence-transformers imports heavy PyTorch wheels (~800MB), instantly exceeding 1GB serverless RAM caps and crashing containers.

✓ FastEmbed ONNX (70% Less Memory)

Replaced PyTorch with pure quantized ONNX runtime (bge-small-en-v1.5). Cold-starts in 2.2s and peaks at just 423MB RAM under full load.

✕ 2. Shared-Disk Data Contamination

Persistent Chroma/SQLite files stored on disk retain previous users' confidential medical files, causing multi-tenant data leakage.

✓ In-Memory Isolation with LRU Eviction

Vector collections live exclusively in process RAM (chromadb.EphemeralClient) tied to session UUIDs with an LRU cap (max 10) to prevent memory leaks.

✕ 3. Hallucinations & Wasted API Bills

Irrelevant queries trigger full LLM completions, wasting API budget while fabricating answers to off-topic or unanswerable medical questions.

✓ Two-Layer Refusal Gate (<25ms, 0 Tokens)

Cosine similarity threshold gate ($s < 0.48$) intercepts unrelated queries in 18ms with 0 LLM tokens, backed by strict XML prompt grounding.
