❌ The Production RAG Problem

Most tutorial RAG implementations fail in real-world deployment. They pull in heavy PyTorch wheels (~800MB) causing Out-Of-Memory (OOM) container crashes, store documents on shared disks leaking data between users, and hallucinate answers when asked out-of-domain queries.

✅ The ClinicDocs AI Solution

Built an enterprise-ready architecture with FastEmbed ONNX (slashing RAM by 70%), an in-memory ephemeral ChromaDB layer with LRU eviction for zero-disk retention, and an empirical Two-Layer Refusal Gate that cuts latency on out-of-domain queries to <25ms.

1

Two-Layer Refusal

Cosine similarity gate ($s < 0.48$) intercepts unrelated queries in 20ms using 0 LLM tokens. Strict prompt grounding handles near-topic unanswerable questions.

2

Ephemeral Isolation

Chroma collections are strictly tied to unique session UUIDs in RAM with LRU eviction cap (max 10). Guaranteed zero multi-user cross-contamination.

3

FastEmbed ONNX

Replaced PyTorch with pure ONNX runtime (bge-small-en-v1.5). Cold-starts in 2.2s and peaks at only 423MB RAM under full load.

4

Physical Citations

Normalizes 0-indexed PyPDF pages to 1-indexed numbers (page + 1). Outputs source document name, similarity %, and context snippet.
